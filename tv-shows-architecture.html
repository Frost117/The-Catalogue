TV Shows Multilingual Platform

Architecture & Project Requirements — Vue.js + Umbraco Compose + Umbraco Cloud v17

Project Overview

Frontend

Vue.js SPA on Cloudflare Pages

A multilingual single-page application (EN, DA, VI) that displays TV show catalogues, detail pages, and member comments. Hosted on Cloudflare Pages for edge delivery. All content is fetched via a single GraphQL endpoint from Umbraco Compose.

Content Hub

Umbraco Compose (GraphQL API)

Acts as the unified content aggregation layer. Merges three data sources into one GraphQL schema: TV Maze show data, translated content from Umbraco Cloud, and member comments. The frontend only ever talks to Compose.

CMS

Umbraco Cloud v17

Managed by content editors for Danish and Vietnamese translations of TV show metadata (titles, descriptions, genres). Also hosts UI Builder for backoffice comment moderation. The REST API is used for the comment write path.

External API

TV Maze API

Public REST API providing the canonical English-language TV show catalogue: titles, summaries, cast, episode guides, images, schedules, and ratings. The source of truth for show identity.

Key Principles

Principle

Single GraphQL Gateway

The frontend never calls TV Maze or Umbraco Cloud directly for reads. Compose is the only read surface, keeping the frontend simple and decoupled from backend data source topology.

Principle

Separated Read / Write Paths

Reads go through Compose GraphQL. Writes (comments) go directly from the frontend to the Umbraco Cloud REST API, bypassing Compose. This keeps the write path simple and avoids Compose becoming a write-through proxy.

Principle

English-first, Manual Translations

TV Maze provides the English baseline. Content editors in Umbraco Cloud maintain DA and VI translations manually. Compose merges these into locale-aware content nodes served via GraphQL.

Read Path — Fetching TV Show Data

1
User visits page (e.g. /da/shows/breaking-bad) Vue.js router resolves locale (DA) and show slug. Fires a GraphQL query to Compose with locale and show identifier.
2
Compose receives GraphQL request Compose resolves the query against its internal merged content graph. The graph is pre-built from three ingested sources.
3
Source A — TV Maze (English baseline) Compose has previously ingested show data from TV Maze REST API (title, summary, cast, episodes, images, rating). This is the canonical EN content and the show's identity key.
4
Source B — Umbraco Cloud (DA/VI translations) Compose pulls translated content maintained by editors in the Cloud v17 backoffice. Translations are linked to TV Maze show IDs. For DA locale requests, these override the English defaults.
5
Source C — Umbraco Cloud (Comments) Compose reads the comments table managed by UI Builder. Comments are keyed by TV Maze show ID and include member ID, text, timestamp.
6
Compose returns merged response A single GraphQL response containing: show metadata (localized), episode list, cast, images, rating, and paginated comments. Frontend renders the page.

Write Path — Posting a Comment

1
Authenticated member submits comment Vue.js collects show ID, comment text, and the member's auth token. Sends a POST request directly to the Umbraco Cloud REST API endpoint.
2
Umbraco Cloud validates and persists The REST API validates the auth token, checks rate limits, sanitizes input, and writes the comment to the database table that UI Builder manages.
3
UI Builder reflects new comment Backoffice editors can see the new comment in the UI Builder dashboard for moderation (approve, flag, delete).
4
Compose picks up comment on next read The next GraphQL query for this show's comments will include the newly written record (subject to Compose's sync/cache refresh interval).
Latency consideration: There may be a short delay between writing a comment (REST to Cloud) and seeing it in GraphQL responses (Compose sync). The frontend should handle this with optimistic UI updates — show the comment immediately in the local state while the backend catches up.

  • Content source: Umbraco Cloud Content Delivery API
  • Content source: Umbraco Cloud DB (comments)

  • Locale-aware field resolution

CMS

Umbraco Cloud v17

  • Content types for translated show metadata
  • Language variants: DA, VI
  • TV Maze ID as the foreign key field
  • Content Delivery API for translations
  • Custom REST endpoint for comment writes

Backoffice

UI Builder — Comment Management

  • Custom table: ShowComments
  • Fields: ShowId, MemberId, Text, CreatedAt, Status
  • Status workflow: Pending → Approved / Flagged / Deleted
  • Filters by show, date, status
  • Bulk actions for moderation
External

TV Maze API

  • GET /shows — full catalogue
  • GET /shows/:id — show detail
  • GET /shows/:id/episodes — episode list
  • GET /shows/:id/cast — cast info
  • Rate limiting: ~20 calls/10 seconds
  • No auth required (public API)

Internationalization Strategy

i18n

Content Localization Model

  • UI chrome (nav, buttons, labels) — managed in vue-i18n JSON files, shipped with the build
  • Show metadata (title, description) — EN from TV Maze, DA/VI from Umbraco Cloud editors
  • Comments — stored in the language they were written in (no translation)
  • Fallback chain: requested locale → EN → empty
i18n

Locale Routing

  • URL pattern: /:locale/shows/:slug
  • Default locale detection via Accept-Language or stored preference
  • Locale switcher component persists choice
  • Compose GraphQL accepts locale parameter and resolves appropriate content variant

Technical Risks & Open Decisions

Risk

Comment Write Path Bypasses Compose

The frontend writes directly to the Umbraco Cloud database via REST. This means the Cloud REST API is exposed to the public internet. Requires robust auth validation, rate limiting, input sanitization, and CORS restrictions. Consider a Cloudflare Worker as a thin proxy to add an extra layer.

Risk

Compose Sync Latency

There's an eventual consistency gap between a comment being written to Cloud and appearing in Compose's GraphQL responses. The frontend needs optimistic rendering, but also needs to reconcile if a comment fails server-side validation or moderation.

Risk

TV Maze API Reliability

TV Maze is a free public API with rate limits. If it goes down or throttles, Compose needs to serve stale cached data gracefully. Need a caching and retry strategy in Compose, and monitoring for API health.

Risk

Translation Coverage Gaps

Not all shows will have DA/VI translations. The fallback-to-English strategy works, but the UX should clearly indicate when content is displayed in a non-requested language. Editors need a dashboard showing untranslated content.

Decision

How Does Compose Ingest Comments?

Does Compose poll the Cloud database on a schedule? Subscribe to webhooks? Read from a shared database connection? This is a key architectural decision that affects freshness, coupling, and operational complexity.

Decision

Member Auth Architecture

Members authenticate against Umbraco Cloud. The Vue.js frontend needs to obtain and manage tokens. Does the frontend use Umbraco's member login endpoint directly, or is there an OAuth/OIDC flow? Token refresh strategy for long sessions?

Decision

Compose Content Modelling

How are TV Maze shows represented in Compose? As imported content nodes? As external data source references? How are translations linked — by a shared TV Maze ID field? The content model in Compose determines the GraphQL schema shape.

Decision

SEO Rendering Strategy

Pure SPA with client-side rendering will hurt SEO for show pages. Options: Nuxt.js for SSR/SSG, Cloudflare Workers for dynamic rendering, or a pre-rendering service. This affects the build pipeline and deployment model significantly.

3

4
Prototype the comment write ↔ read loop Build the riskiest path first: member posts comment via REST → Cloud persists → Compose picks up → GraphQL returns it. Validate the latency and consistency model.
5
